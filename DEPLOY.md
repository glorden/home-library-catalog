# Деплой

**Черновик.** Полностью актуализируется на шаге 8 (первый реальный деплой на
VPS); до тех пор часть команд ниже не проверена на практике.

## Переменные окружения

Локальная разработка через Docker Compose использует значения по умолчанию
из `docker-compose.yml` (см. `environment:` секции). На VPS все секреты
задаются через `.env` в корне репозитория — этот файл никогда не коммитится.

Обязательные переменные (список пополняется по мере шагов 2-5):

| Переменная | Появится на шаге | Назначение |
|---|---|---|
| `DEBUG` | 1 | режим отладки FastAPI/uvicorn |
| `DATABASE_URL` | 2 | строка подключения к Postgres |
| `SETTINGS_ENCRYPTION_KEY` | 4 | ключ Fernet для шифрования API-ключей AI-провайдеров |
| `SESSION_SECRET_KEY` | 5 | ключ подписи session cookie (itsdangerous, HMAC) |
| `SHOWCASE_PUBLIC` | 5 | `true`/`false` — временно закрыть публичную витрину целиком |
| `AI_EXTRACTION_DAILY_LIMIT` | 5 | дневной лимит вызовов AI-распознавания (по умолчанию 30) |

## Требования к Postgres (с шага 6)

Миграция шага 6 сама ставит расширение (`CREATE EXTENSION IF NOT EXISTS
pg_trgm`) — отдельного шага в процедуре деплоя не требуется, но образ
Postgres должен включать contrib-модули. `postgres:16-alpine` (используется
в `docker-compose.yml`) их включает — проверено вживую. Если образ на VPS
когда-нибудь поменяют на более урезанный, это первое, что стоит перепроверить.

## Продовый Compose (план, шаг 8)

`docker-compose.prod.yml` — overlay поверх `docker-compose.yml`:

- **nginx** — reverse proxy перед `app`; отдаёт обложки книг не напрямую, а
  через `X-Accel-Redirect` (FastAPI-роут проверяет права на копию → просит
  nginx отдать файл из `internal;`-location). Без этого паттерна флаг
  `copies.is_public` ничего не значит — любую обложку можно будет скачать по
  прямой ссылке, даже приватную.
- **nginx** — `limit_req_zone` на `/login`, чтобы не гонять единственный
  admin-пароль на брутфорс без вообще какого-либо троттлинга.
- **Certbot** — выпуск и автопродление сертификата Let's Encrypt.
- `restart: unless-stopped` на всех сервисах.
- **HTTPS обязателен и для PWA** (шаг 7, реализовано) — service worker не
  регистрируется на незащищённом origin вне localhost; без сертификата не
  заработают ни установка приложения, ни офлайн-заглушка. На localhost всё
  это уже проверено вживую (см. ARCHITECTURE.md) — здесь первый раз
  проверяется поверх настоящего HTTPS.

## Бэкапы

- `pg_dump` по расписанию (cron на VPS или отдельный контейнер) —
  **за пределами VPS** (S3-совместимое хранилище, другой сервер и т.п.).
- Том с фото (только обложки после шага 3 — растёт медленно) — туда же.
  Том Docker сам по себе — не бэкап; обложки невосстановимы в отличие от БД,
  которую в теории можно восстановить по памяти/переввести.

## Процедура (черновик, уточнится на шаге 8)

1. Чистый VPS, установлен Docker + Docker Compose plugin.
2. `git clone` репозитория.
3. Скопировать `.env.example` → `.env`, заполнить реальными значениями.
4. `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build`.
5. Выпустить сертификат через Certbot-контейнер, проверить автопродление.
6. Создать единственного пользователя: `docker compose exec app python -m app.cli create-admin --email you@example.com`.
   Пароль забыт — `docker compose exec app python -m app.cli reset-admin-password`
   (без email-инфраструктуры; заодно инвалидирует все ранее выданные session cookie).
7. Проверить: домен открывается по HTTPS, публичная витрина доступна без
   входа, вход под своей учёткой открывает добавление книг; отдельно —
   service worker регистрируется на боевом домене (DevTools → Application →
   Service Workers), манифест проходит без ошибок, и «добавить на экран»
   реально работает с телефона (единственная проверка PWA, которую нельзя
   было сделать на шаге 7 без HTTPS — см. ARCHITECTURE.md).
8. Настроить бэкапы (см. выше) и убедиться, что они реально доезжают за
   пределы VPS, а не просто выполняются "успешно" локально.
