# Процесс разработки

Соло-проект, поэтому процесс лёгкий — ровно настолько, чтобы не мешать
скорости, но оставлять след в репозитории, а не только в истории чата.

## Ветвление

Один `main`, короткие ветки на issue (`feat/photo-upload`,
`fix/dedup-false-positive`), squash-merge даже соло — это даёт линейную
историю и PR-diff как самопроверку перед мержем. Без `develop`/gitflow —
не оправдано для одного мейнтейнера.

## CI

С шага 1: GitHub Actions гоняет `ruff check` + `ruff format --check` +
`pytest` с реальным `postgres:` сервис-контейнером (см.
`.github/workflows/ci.yml`) — так миграции и full-text/trigram-функциональность
(с шага 2) реально проверяются, а не мокаются. Actions бесплатны для
публичных репозиториев. Один пин версии Python (3.12), без матрицы — не
оправдана для одного мейнтейнера.

Dependabot (`.github/dependabot.yml`) — `pip` + `docker` + `github-actions`,
еженедельно.

## Лейблы

- `type: feature` / `type: bug` / `type: chore` / `type: docs`
- `area: ai` / `area: auth` / `area: pwa` / `area: search` / `area: infra`
- `priority: mvp` / `priority: post-mvp` — отражает разделение MVP/после-MVP
  из `idea.md`
- `good first issue` — на случай внешних контрибьюторов у open-source проекта

## Milestones и доска

GitHub Milestones = Шаг 1 … Шаг 8 (см. план реализации) + `Post-MVP` для
бэклога (бэкапы БД/фото за пределы VPS — сознательно отложены на шаге 8,
см. DEPLOY.md; импорт из библиотек, CSV-экспорт, история цен, рекомендации,
доп. AI-провайдеры, отдельная видимость по фото, вынос авторов в отдельную
таблицу). Project board (Todo / In Progress / Done), сгруппированный по
Milestone — этого достаточно, без дополнительных инструментов.

## Issue/PR шаблоны

Простые markdown-шаблоны (`.github/ISSUE_TEMPLATE/*.md`), не YAML-формы —
меньше поддержки для одного человека. PR-шаблон
(`.github/pull_request_template.md`) — короткий чек-лист (тесты, миграция
при изменении схемы, проверка в браузере для UI).

## Уязвимости

Встроенная GitHub-фича **private vulnerability reporting** вместо личного
email в `SECURITY.md` — не нужно решать, публиковать ли личный адрес в
публичном репозитории.

## Лицензия

MIT — простейшая, самая пермиссивная, минимум трения для личного проекта
каталогизации без реалистичного риска "кто-то сделает платный SaaS-форк",
который оправдывал бы AGPL.
